# 备份与保留

> 文档状态：部分实现
> 适用范围：运维 / 数据保护 / 灾难恢复
> 最后更新：2026-06-26

## 1. 文档目的

本文档说明 OJOS 需要备份的数据范围、恢复一致性要求和保留策略。当前仓库提供存储模型和部署入口，但自动备份调度需要按生产环境实现。

## 2. 适用范围

适用于部署人员、DBA、运维人员和负责 artifact storage 的开发者。

## 3. 当前实现

最小备份集包括 PostgreSQL、题目包 artifact、提交源码 artifact 和结果 artifact。数据库记录与 `result.json`、源码文件、题目包文件必须保持一致。

## 4. 目标设计

生产环境建议使用对象存储和自动快照，建立每日、每周和发布前备份策略。备份应加密、可校验、可恢复，并记录恢复演练结果。

## 5. 关键流程

备份时先冻结或记录数据库一致性点，再备份 artifact storage。恢复时先恢复数据库，再恢复 artifact，最后通过提交详情和题目包校验确认一致性。

建议恢复顺序：

1. 停止写入流量或切换到维护模式。
2. 恢复 PostgreSQL 到指定时间点。
3. 恢复 artifact storage 到同一时间点或最近一致快照。
4. 启动 Control Plane。
5. 执行登录、题目详情、题目包校验、提交详情和结果文件读取检查。
6. 恢复 worker 评测能力，确认新提交可以进入终态。

如果数据库比 artifact 新，可能出现记录存在但文件缺失；如果 artifact 比数据库新，可能出现孤儿文件。恢复演练应记录这两类不一致的处理办法。

## 6. 配置说明

Control Plane 的 artifact root 来自部署配置。PostgreSQL DSN 和对象存储凭据不能写入文档或 Git。备份脚本如进入 `scripts/`，必须有文件头和正式文档引用。

## 7. 安全边界

备份中可能包含用户源码、题目数据和提交结果，应加密存储，限制访问权限，禁止上传到不受控位置。

## 8. 验收方式

定期执行恢复演练：恢复后登录、题目详情、题目包校验、提交列表、提交详情和 case 结果都应可用。

生产前至少完成一次“空库恢复演练”。演练结果应记录备份时间、恢复时间、数据量、恢复耗时、校验命令和失败项。当前仓库没有内置生产备份脚本，因此本文档状态为“部分实现”；部署方需要按实际数据库和对象存储方案补充正式脚本。

## 9. 常见问题

- 只恢复数据库导致提交详情缺文件：必须同步恢复 artifact。
- 恢复后题目包校验失败：检查 storage 路径和文件权限。
- 备份过大：配置保留周期和对象存储生命周期。
